# OS choice

Checked against current project documentation on 2026-07-24.

## GrapheneOS

GrapheneOS does not provide a production build for the OnePlus Nord 2T. Its
[supported-device list](https://grapheneos.org/faq#supported-devices) contains
specific Pixel devices. Its
[build documentation](https://grapheneos.org/build) explains that generic and
emulator builds lack the complete device-specific kernel, firmware and
security integration needed for a production GrapheneOS release.

Installing a generic image on this phone would therefore not turn it into a
supported GrapheneOS device. There is no official GrapheneOS GSI for `karen`.
Porting selected GrapheneOS platform changes on top of a new device port would
be a GrapheneOS-derived custom ROM, not GrapheneOS with its documented security
properties or update support.

## LineageOS

The [LineageOS device list](https://wiki.lineageos.org/devices/) has no
`CPH2399` or `karen` entry. The listed device `oscaro` is the Snapdragon-based
OnePlus Nord CE 2 Lite, not this MediaTek Nord 2T. LineageOS's
[FAQ](https://wiki.lineageos.org/faq) is explicit that an unlisted model is not
supported even when it appears similar to a listed model.

No maintained unofficial fork with current signed releases and OTA support was
found. The known 2022–2023 trees are useful only as bring-up references:

- [oneplus-karen-roms](https://github.com/oneplus-karen-roms), four stale
  Android 12-era repositories last updated in October 2022;
- [Nord2T organization](https://github.com/Nord2T), an incomplete Evolution
  X/Pixel Experience attempt;
- [ArrowOS device tree](https://github.com/abhi0-tech/android_device_oneplus_karen),
  four commits from April 2023;
- autogenerated TWRP device-tree attempts.

They mix `karen` and Nord 2 `denniz` material, rely on Android 12-era blobs,
publish no verified current ROM and include incomplete or unsafe policy
shortcuts. Do not flash their products.

The old
[unofficial TWRP tree](https://github.com/oneplus-karen-roms/android_device_oneplus_karen-twrp)
is also not a current installation route. It embeds an OxygenOS A.15-era
4.14.186 kernel from 2022, while `.3001` runs a 4.19.191 kernel built in 2026.
Its own issue tracker reports Android 13 data-mount failure, before this
phone's Android 14 baseline.

## Other privacy distributions

The current CalyxOS and /e/OS supported-device lists also do not include this
model. A Treble-compatible GSI can be useful for temporary developer bring-up,
but it does not automatically provide maintained kernel, firmware, camera, IMS,
fingerprint, NFC or verified-boot support.

## Security conclusion

“No Google apps” and “secure OS” are separate properties. A self-built image
would need an unlocked bootloader and proprietary MediaTek firmware. There is
no documented supported workflow for enrolling a custom AVB key and relocking
this model. Treat custom-ROM testing as a permanent loss of the stock trust
state until exact stock firmware has been restored and the bootloader safely
relocked.

For this hardware, current signed OxygenOS with a locked bootloader is the
stronger security baseline than an abandoned or hand-built ROM. Reversible
package hardening can improve privacy, with the compatibility and Mainline
update trade-offs documented in [privacy.md](privacy.md).

If the primary requirement is a security-centred custom OS with routine
updates and a relocked bootloader, migrating to a currently supported
GrapheneOS device is the realistic route.
